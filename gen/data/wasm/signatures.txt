# the stack signatures opcode.def's type columns do not state
#
#   sig <Name> | pops="<types>" pushes="<types>"
#
# opcode.def states an instruction's result types (tr, tr2) and its parameters (t1, t2, t3), and its
# `___` for none, so an instruction whose columns state its whole type takes them: it pops t1, t2 and
# t3 deepest first and pushes tr and tr2. a memory instruction's address, its t1, is the address type
# of the memory its memarg names, operand 0, under memory64 an i64, so the generator reads it as `<0>`
# by that rule and no line restates it. a line here states the whole signature of an instruction
# whose columns do not, overriding them, in masc's spelling of stack types (masc.core.stream): a type
# name, `<n>` for the types operand n states, `$n` for a type variable, `results` for the function's
# results and `...` for the polymorphic stack. an index operand states its entry's types: a function
# or type index its function type, params where popped and results where pushed, a block type its
# params and results, a label the types a branch to it carries, a tag its params, a local or a
# global its value type, and a memory or a table its address type.
#
# every line cites the WebAssembly Specification release 3.0, tag wg-3.0, its index of instructions
# (document/core/appendix/index-instructions.py, the type column), as `index`
#
# limits: the type language holds no reference type built from an operand nor a nullability, so a
# table's element type, a reference an instruction takes and the length operand of a copy between two
# address types are type variables. br_on_non_null's label carries its reference last, which the
# instruction pushes only to the branch, so its signature states the label's types both ways. else and
# end are typed by the block the stream holds open, so their columns' empty signature stands
