# the value types and heap types of wasm, by the text name and the binary code each is spelled by
#
#   type <name> | <code> <feature>*   a value type a single byte spells, its text name the shorthand
#   heap <name> | <code> <feature>*   an abstract heap type, its code the byte of its s33 that a type index never is
#
# the features after a code are those a type requires, every one of them, as features.txt names an
# instruction's, none for wasm 1.0's: v128 is simd128's, funcref and externref and their heap types
# reference-types', exnref and exn exception-handling's and the rest the gc proposal's, as `changes`, the
# appendix's change history (document/core/appendix/changes.rst), names the types each proposal adds. a
# reference to a type index, or a non-null one, is function-references' (changes, release 3.0, typeful
# references), which the kinds admit
#
# a reference type is spelled `(ref null? <heap type>)` and a byte 0x63 or 0x64 before its heap type,
# which the kinds read from these. the stack types of every signature are spelled by the value types'
# names (masc.core.stream), and opcode.def's I32, I64, F32, F64 and V128 name the first five. opcode.def
# states no code, so no line overrides it
#
# every line cites the WebAssembly Specification release 3.0, tag wg-3.0: 5.2 is
# 5.2-binary.types.spectec and 6.2 is 6.2-text.types.spectec
