# the wasm feature catalog, written by masc from the sources below
#
# a row is a feature a selection holds: a proposal the WebAssembly specification release 3.0 merged, or
# the threads proposal, which 3.0 does not hold. each row's name is llvm's target feature name
# (llvm/lib/Target/WebAssembly/WebAssembly.td), the spelling a wasm object's target_features section
# names it by, and a feature llvm has no name for takes wabt's `--enable-<name>` spelling: memory64 and
# function-references. llvm's two sub-features bulk-memory-opt and call-indirect-overlong are rows of
# their own, since llvm and its objects name them. an implication is stated only where a source states
# it, and the source is named at the row
#
# wasm has no execution state code switches, so the catalog states no axis. the width of an address is
# a memory's own type, which the memory64 feature admits, and the architecture wasm64 enters memory64
#
# the sources, read at the revisions named:
#   WebAssembly Specification release 3.0, tag wg-3.0 (9d36019973201a19f9c9ebb0f10828b2fe2374aa)
#     Appendix: Change History, Release 2.0 and Release 3.0, which list the proposals each release merged
#   WebAssembly threads proposal, commit cc535ada1aa21cfaa3cabf3ac73b89acef78a0a0, proposals/threads/Overview.md
#   llvm-project 7ddb67460b168b17ebb263dc99bf956b56d7e517, llvm/lib/Target/WebAssembly/WebAssembly.td
#     the feature names and their implications
#   wabt 1.0.42, include/wabt/feature.def: the spellings memory64 and function-references
#
# a row's revision is none: no feature states a version a selection could spell
