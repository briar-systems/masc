# a line names rows as the mnemonics topic's do and states the relation of each (gen.relation), its operands by their
# numbers in XED's order: the register written, the register read and the immediate added, for lea the memory operand
# whose base it reads and whose displacement it adds, or `formed` the immediate a mov writes whole. a relation holds in
# the low bits of the narrower register it names, so a 32-bit add's states nothing of the bits its write zeroes above
# them. an apx nd row writes its new data destination, operand 0, from operand 1. a line naming no row, or an operand a
# row lacks, is refused
#
# a trap line states the trap a row takes, which XED's category names without its kind: `returns=yes` for one whose
# handler resumes at the next instruction, `returns=no` for one nothing falls through after (gen.control), and
# `conditional=yes` for one some values skip. what it writes by the architecture XED states, as syscall's rcx and r11.
# every row of XED's SYSCALL and INTERRUPT categories has a line, and hlt has none: it waits at the privilege it
# requires and resumes at the next instruction, as risc-v wfi does, and its #GP below that privilege is any
# privileged instruction's
#
# a count line states the general register, by its 16-bit name, whose value decides how many elements a row's accesses
# no operand names cover, which the row reads as XED states and at the width XED states it, as cx of rep xcryptecb: the
# access covers that many of XED's elements, a count the register decides rather than one equal to it. a string row's
# count under a repeat prefix is rcx by its address size, which the generator states from the row's repeat prefix
# alone (Intel SDM 325462-093US Vol 2B REP/REPE/REPZ/REPNE/REPNZ), so no line names one. a stack line states a change
# to the stack pointer no delta of the stack contract states, as enter's, whose allocation and nesting level's copies
# XED does not tell apart from push's
#
# an order line states how a row orders the memory accesses around it (gen.order), the one field it reads its order
# from `lock`, whether the row's f0 is there, so a locked row's order is its prefix's. an ordered line names rows that
# must state an order, as every locked row must, so a fence or an implicitly locked access no order line names is
# refused
