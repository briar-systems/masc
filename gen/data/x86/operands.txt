# how the template of a row writes its plain operands where llvm writes them otherwise than XED orders them
#
#   <ICLASS> [op=<opcode>] [size=o16|o32|o64] [width=16|32|64] [prefix=p66|pf3|pf2] [w=0|1] [form=reg|mem|ptr] |
#   <written> | <cites> | <XED's order>
#
# a row's template writes its plain operands, those not evex's opmask, `{z}`, rounding control or apx's default flags,
# in XED's order, each followed by the opmask and `{z}` that decorate it. x87's st(0) beside another operand is not
# written, as llvm-objdump 23.1.1 writes `fadd dword ptr [eax]` and `fcom st(1)`. a line names rows as the mnemonics
# topic's do, `form=` narrowing it to register or memory forms, and states the operands the rows write, in order, each a
# word: an operand's number in XED's order, its hole's format after a colon, or text written in its place, as the `st`
# llvm's asm string spells for st(0), or `-` alone for none. a memory operand's format is the size word written before
# it, `-` for none, where llvm's operand type is another than its access width: i8mem's byte of a prefetch, and
# opaquemem's none. an operand a line leaves unwritten is one the row fixes, and a row whose line leaves one unwritten
# with no text in its place reads too with every operand in XED's order, as llvm-mc 23.1.1 reads `vmrun rax` as the
# `vmrun` llvm-objdump prints. the last field is XED's order, the numbers of the rows' plain operands
