# the x86 decode dispatch keys, in the order the dispatch prefers them: the opcode map and byte, then the code width,
# ModRM's mod and reg, the prefixes an operand size, a rex2 prefix and a mandatory prefix read, then f0, 67, the vector
# length, evex.b, ModRM.rm, the rex bits of a register the opcode's low bits hold, and apx's evex payload
#
#   key <name> | lo=<bit> len=<bits>     bits lo to lo + len - 1 of the match word
#
# the match word is masc's own, one word of what tells x86 rows apart, read under the code width through the prefix
# scan (masc.isa.x86.field.scan), so a byte is a prefix or an opcode as the width makes it. the generator states each
# row's cubes over these fields by their names, and masc's key module reads each field by the reader of its name,
# x86_key.<name>:
#   map:    the encoding space times 32 plus the opcode map, as vex's five bits of map reach 31
#   opcode: the opcode byte
#   mode:   the code width, 0 for 16, 1 for 32 and 2 for 64 bits
#   direct: 1 when ModRM.mod is 3, naming a register, else 0
#   reg:    ModRM.reg
#   osz:    1 when a 66 prefix is there, or a vex or evex pp of 01
#   w:      the W bit of a rex, rex2, vex or evex prefix
#   rex2:   1 when a rex2 prefix is there
#   rep:    the last of f2 and f3, or a vex or evex pp of 11 or 10, 2 for f2 and 3 for f3, 0 for neither
#   lock:   1 when f0 is there
#   asz:    1 when 67 is there
#   vl:     vex.l, xop.l or evex.l'l, 0 for a legacy instruction
#   b:      evex.b, 0 outside the evex space
#   rm:     ModRM.rm
#   rexb:   rex.b or rex2.b3, plus 2 for rex2.b4, 0 with neither prefix
#   aaa:    evex.aaa, 0 outside the evex space
#   v4:     evex.v' as the bits hold it, uninverted, which apx's ccmp and ctest read as their condition's fourth bit
# which keys the dispatch reads, and in what order, is masc's own choice, so no line overrides XED, which states the
# bits each pattern fixes and no key
