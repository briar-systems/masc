#
#   <ICLASS> byte=<opcode byte> [address=a16|a32|a64] | independent [keeps=<register>] | <cites> | -
#
# Intel's "Data Operand Independent Timing Instructions" (intel.com developer article 768547, updated 2026-02-23,
# version "Latest", Table 1 "Documented Data Operand Independent Timing Instructions") names each instruction by
# XED's ICLASS and one opcode byte, in no space or map: a line names every row of the ICLASS whose opcode byte it is,
# legacy, vex and evex alike, and each of the eight bytes of a row whose opcode's low three bits hold a register. the
# table read here is 840 entries, its "Mnemonic" and "Opcode" cells in page order, one tab apart and one entry a line,
# of sha256 17a8e95e21175d41610aff8a9bcd6dac81323af6bcf3164884e0cea30ed315c0. the page states no licence and sits
# under Intel's terms of use, so it is not vendored: each line restates one entry as a fact, citing it
#
# a row a line names depends on no input under doitm=on (IA32_UARCH_MISC_CTL.DOITM, Intel SDM 325462-093US Volume 1,
# 18.1) and on every input otherwise, but for the register it keeps there: footnote 1 makes the REP_ entries' latency
# vary by the count in *CX, so each keeps the count register of its address size. every row no line names is
# dependent. a line naming no row, two lines naming one byte of a row, and a row whose opcode holds a register named
# at some of its eight bytes alone, are refused. the address of an access and the condition and target of a transfer
# always matter, and the walk reads them from the effect
#
# the REP_ mnemonics carry the footnote's marker 1, dropped here. the list's PEXTRW 0x15 is the form XED names
# PEXTRW_SSE4, and its VPEXTRW 0xc5 is XED's VPEXTRW and, of evex, VPEXTRW_C5, so those lines name XED's ICLASS. the
# list names no locked form, and XED's _LOCK ICLASSes stay dependent. AMD publishes no list of data-independent timing
# instructions, so no line rests on one. XED states no timing, so no line overrides it
