# what each instruction accesses through its pointer and image operands, and how barriers and atomics order the
# accesses around them, which the grammars do not state, since they name every pointer and image an IdRef
#
#   access <set> <opname> <operand> | read|write|both element=pointee|unstated|<bits> [count=type|unstated|<n>]
#                                     [size=<n>] [forming=<n>[,<n>...]] [governor=<n>]
#   access <set> <opname> <operand> | none
#   order <set> <opname> | before=<kinds> after=<kinds> [semantics=<n>] [failure=<n>] [scope=<n>] [execution=<n>]
#
# <set> is `core` for the core grammar or the name an extended set is imported by, and operands are numbered as the
# set's grammar numbers the instruction's own, from 0, `-` for an access no operand addresses. an access covers its
# element times its count: each element the pointer's pointee, `bits` wide, as a half of vload_half, or of a width the
# types do not fix (`unstated`), as a texel; as many as the components of the result type (`type`) or of the type of
# operand <n>, as many as the value of operand <n> decides (`size`), one when the line names neither, or a count no
# operand decides (`unstated`), as a sample's filtering or the string printf reads. `forming` names the further
# operands forming the address, as an offset in elements or an image coordinate and its image operands, and
# `governor` the operand deciding whether it accesses at all. `none` states an operand the instruction accesses
# nothing through, as an access chain's base, which it only addresses, or with `-` an instruction that accesses
# nothing. an order line states the kinds of access before and after it that an instruction may order, as letters of
# r (reads), w (writes), i (device input) and o (device output), its memory semantics operands deciding how, the
# `failure` one when its access writes nothing, its memory scope among which agents, and its execution scope which it
# waits for.
#
#   quiet <class> | none
#
# a quiet line names a class of the core grammar whose instructions access nothing and order nothing. every core
# instruction of any other class has an access or order line, `access core <opname> - | none` for one that accesses
# nothing, no instruction of a quiet class has one, and every memory semantics operand has an order line naming it, so
# a core row that states no access accesses nothing. an instruction that runs code the module does not show, as a
# call or a ray trace, states an access no operand addresses of what that code may access. an extended set's grammar
# files its instructions under no class, so each of its pointer operands has a line here
#
# core lines cite the SPIR-V 1.6 rev 7 specification, GLSL.std.450 lines the GLSL.std.450 Extended Instruction Set
# 1.00 rev 2, as `GLSL`, OpenCL.std lines the OpenCL Extended Instruction Set Specification 1.00 rev 2, as `OpenCL`,
# and NonSemantic.Shader.DebugInfo.100 lines its specification rev 6, as `DebugInfo`
