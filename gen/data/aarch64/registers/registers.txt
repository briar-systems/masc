# the AArch64 register families masc's register file is derived from, written by masc from the sources below
#
# sources, read as published:
#   aadwarf64: ARM-software/abi-aa bd017eeca341c06915b9a02ae111b480416d248f, aadwarf64/aadwarf64.rst, section "DWARF register
#     names". the dwarf numbers. a register the table does not number has none. its thread id registers 35 to 39 are system
#     registers, its TPIDRRO_ELO and TPIDR_ELO read as tpidrro_el0 and tpidr_el0, and ELR_mode and RA_SIGN_STATE are
#     pseudo-registers no instruction names
#   CodeViewRegisters.def: llvm-project 7ddb67460b168b17ebb263dc99bf956b56d7e517, llvm/include/llvm/DebugInfo/CodeView/
#     CodeViewRegisters.def, the CV_REGISTERS_ARM64 block, which is cvconst.h's CV_ARM64_*. the codeview numbers: ARM64_FPSR 220
#     and ARM64_FPCR 221 are the fpsr and fpcr system registers, and wsp, v, z, p, ffr, vg, pc and za have no number
#   AARCHMRS 2026-09_rel Registers.json, the system register model the aarchmrs source vendors: every system register is the
#     encoding an A64.MRS or A64.MSRregister accessor of a register of the AArch64 state names, as the system class reads it
#   the Arm Architecture Reference Manual for A-profile (DDI 0487) pseudocode, as Arm publishes it in rems-project/sail-arm
#     1bf2e5574ba9d704639a28401b6a387dcb113cae (BSD-3-Clause-Clear), arm-v9.4-a/src/v8_base.sail unless named, at these lines:
#       X_set 7434: a write of w<n> or x<n> sets _R(n) to ZeroExtend(value, 64), and x31 is discarded. so w zeroes through x, and
#         xzr and wzr discard a write
#       instrs64.sail 609 (add and sub, immediate): a 32 bit result written to sp is SP_set() = ZeroExtend(result, 64). so wsp
#         zeroes through sp
#       V_set 7418: a write of 8, 16, 32, 64 or 128 bits sets _Z[n][vlen-1..0] to ZeroExtend(value, vlen), vlen being VL when sve is
#         enabled and 128 else. so b, h, s, d, q and v zero through z. V_read 22332 reads _Z[n][width-1..0], so those are the low
#         bits of z
#       Z_set 7446, P_set 7360, FFR_set 7004: a write of z, p or ffr is VL, VL / 8 or VL / 8 bits wide, and the storage past it up to
#         MAX_VL 2700 and MAX_PL 2704 is not part of the register (MAX_VL is 2048 bits). so each is its own bank and keeps
#       ZAvector_set 31142, ZAhslice_set 31171: horizontal slice s of tile t of element size e is ZA vector t + s * (e / 8), a row of
#         svl bits. so a tile is every (e / 8)th row of the array from its number, and a write of one row keeps the others
#       ZAvslice_set 31201: a vertical slice is written by reading each row of the tile, replacing one element and writing the row
#         back, so a slice lies within its tile and a tile bounds what any slice writes
#   llvm-mc 7ddb674, as a check of the dwarf numbers: `.cfi_offset <n>` read back by llvm-dwarfdump --eh-frame names 0 as W0, 30 as
#     W30, 31 as WSP, 46 as VG, 47 as FFR, 64 and 95 as B0 and B31, 96 and 127 as Z0 and Z31
#
# lines, one record each, fields separated by blanks:
#   quantity <name> <unit> <max> <register> <count>
#     a quantity of `unit` bits times a power of two to `max`, no extension fixing it, measured by the value of `register`, `-`
#     for none, each count of which stands for `count` bits of it, `-` with no register, as vg holds VL in 64-bit granules
#     (aadwarf64, "DWARF register names": VG holds the number of 64-bit granules in an SVE vector register)
#   slot <name> <requirement> <quantity>
#     the slot a width names bound to the quantity while the requirement holds, `-` for always, as one state value named
#     `axis=value`
#   class <class> <kind> <width> <count> <numbers> <pattern> <bank> <extend> <flags> <requires> <dwarf> <codeview>
#     width:    bits, or a slot name for one unit of its quantity per multiplier, or `<slot>/8` for an eighth of that
#     count:    the hardware numbers the class spans
#     numbers:  the numbers that have a register, as `a-b` or `a`
#     pattern:  the register's name, `%` standing for its number
#     bank:     `new` for storage of its own, `of:<class>` for the bank of the register of that class with the same number,
#               or `in:<register>+<bit>` for the bits from `bit` of the bank of the register of another class so named, the
#               class's one register lying there
#     extend:   keep, zeroes or ones
#     flags:    `-` or a comma list of zero, stack, pc, accrued and unspelled
#     requires: `-`, or the extensions of which a selection must hold one, as `sve|sme`, named as the catalog's ids
#     dwarf and codeview: `-`, or the number of the class's first register, the rest following in order
#   tile <class> <slot> <element> <tiles> <pattern> <requires>
#     the tiles of a scaled array of rows of one unit each: tile n of `tiles` is the rows n, n + tiles, n + 2 * tiles and so on, each
#     of `unit / element` rows, all in one bank
#   slices <class> <tile> <direction> <pattern> <requires>
#     the horizontal (`h`) or vertical (`v`) slices of the tiles of tile class `tile`, svl / 8 of them in either direction
#     whatever the element, so the class's count scales with svl. slice s of tile t is number s * tiles + t: a horizontal
#     slice is that row of the array, and a vertical one element s of each of its tile's rows
#   system <class> <width>
#     the system registers, one class numbered o0:op1:CRn:CRm:op2 of the MRS or MSR naming them (DDI 0487, MRS: op0 is 2 + o0),
#     a row for each encoding Registers.json names, named in lower case as its MRS accessor names it, else as its MSR one, and
#     the other's name an alias where they differ, as DBGDTRTX_EL0 of DBGDTRRX_EL0's encoding. the accessors of one register,
#     or of one element of an array, share its bank, as SCTLR_EL12 SCTLR_EL1's. any encoding is an instruction on every machine,
#     trapping where it names no implemented register, so every number of the class encodes and a row requires nothing. the
#     syntax spells a number no row names S<op0>_<op1>_C<n>_C<m>_<op2>, the spelling Registers.json gives the implementation
#     defined space
#   named <register> <flags> <dwarf> <codeview>
#     the flags and debug numbers of a register no class line numbers, as a system register
#   alias <alias> <register>
#   link <register>
#     the register a call leaves the return address in, x30 (DDI 0487, BL: "sets register X30 to PC+4"), whose dwarf number is the
#     return address column
#
# b, h, s, d, q and v are the low bits of z, so they exist under sve or sme as under fp or simd. pn<n> is p<n> read as a
# predicate-as-counter (DDI 0487, "Predicate-as-counter encoding"), the same storage, under sve2p1 or sme2, and zt0 is
# sme2's 512-bit lookup table register (DDI 0487, "ZT0")
#
# the condition flags are bits 31 to 28 of the nzcv system register (DDI 0487, NZCV: N bit 31, Z 30, C 29, V 28), so the flags
# register lies in its bank there, and the syntax spells the system register, never the flags row. codeview's ARM64_NZCV 90 is
# the system register
#
# register number 31 is sp or the zero register by the operand that holds it, so each is a class of count 32 whose only register
# has number 31. z, p and ffr are as wide as the vector length VL outside streaming mode and as the streaming vector length
# SVL in it (DDI 0487, "Effective vector length"), the two differing on an implementation, so their width is the slot zlen,
# which binds vl under streaming=off and svl under streaming=on, and one register file serves both modes. the tiles and their
# slices are svl wide in every mode. the slices are those of the .s tiles alone, the one element size the file states them
# for

quantity vl  128 16 vg 64
quantity svl 128 16 -  -

slot zlen streaming=off vl
slot zlen streaming=on  svl
slot svl  -             svl

class x   general   64   31 0-30 x%   new     keep   -     -       0  50
class w   general   32   31 0-30 w%   of:x    zeroes -     -       -  10
class xzr general   64   32 31   xzr  new     keep   zero  -       -  82
class wzr general   32   32 31   wzr  of:xzr  zeroes zero  -       -  41
class sp  general   64   32 31   sp   new     keep   stack -       31 81
class wsp general   32   32 31   wsp  of:sp   zeroes stack -       -  -
class b   float     8    32 0-31 b%   of:v    zeroes -     fp|sve|sme -  230
class h   float     16   32 0-31 h%   of:v    zeroes -     fp|sve|sme -  270
class s   float     32   32 0-31 s%   of:v    zeroes -     fp|sve|sme -  100
class d   float     64   32 0-31 d%   of:v    zeroes -     fp|sve|sme -  140
class q   float     128  32 0-31 q%   of:v    zeroes -     fp|sve|sme -  180
class v   vector    128  32 0-31 v%   new     zeroes -     simd|sve|sme 64 -
class z   vector    zlen   32 0-31 z%   of:v    keep   -     sve|sme 96 -
class p   predicate zlen/8 16 0-15 p%   new     keep   -     sve|sme 48 -
class pn  predicate zlen/8 16 0-15 pn%  of:p    keep   -     sve2p1|sme2 - -
class ffr predicate zlen/8 1  0    ffr  new     keep   -     sve     47 -
class vg  system    64   1  0    vg   new     keep   -     sve|sme 46 -
class pc  system    64   1  0    pc   new     keep   pc    -       32 -
class nzcv flags    4    1  0    nzcv in:nzcv+28 keep unspelled - -  -
class zt0 vector    512  1  0    zt0  new     keep   -     sme2    -  -

tile zab svl 8   1  za%.b sme
tile zah svl 16  2  za%.h sme
tile zas svl 32  4  za%.s sme
tile zad svl 64  8  za%.d sme
tile zaq svl 128 16 za%.q sme

slices zash zas h zas.h% sme
slices zasv zas v zas.v% sme

system sysreg 64

# fpsr accrues the cumulative exception bits a floating-point instruction sets and never clears (DDI 0487, FPSR: "IDC, IXC,
# UFC, OFC, DZC, IOC ... cumulative")
named fpsr        accrued -  220
named fpcr        -       -  221
named nzcv        -       -  90
named tpidrro_el0 -       35 -
named tpidr_el0   -       36 -
named tpidr_el1   -       37 -
named tpidr_el2   -       38 -
named tpidr_el3   -       39 -

alias fp x29
alias lr x30
alias za za0.b

link x30
