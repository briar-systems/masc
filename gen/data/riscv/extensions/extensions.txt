# the riscv extension catalog, written by masc from the sources below
#
# one set serves rv32 and rv64 and both bases: the width and the base are
# execution state, the axes xlen and base, not extensions. an isa string
# states both, `rv32` or `rv64` its xlen and `i` or `e` its base, and a row
# that exists at one width requires the width's state value. the e base holds
# the i row's instructions on x0 to x15 alone, so it is a base value and no
# catalog row: `e` names no extension, and the e base's instructions are the
# i rows less the registers base=e does not have. the canonical order an isa
# string is read and spelled in is mink's grammar of it, not the rows' order.
#
# sources, all read at the revisions named:
#   riscv-isa-manual 36fdac54a526aedc46c15621c2af0b40905446c9 (2026-10-08)
#     src/unpriv/preface.adoc  the ratified unprivileged modules and their versions
#     src/priv/preface.adoc    the ratified privileged modules and their versions
#     src/unpriv/naming.adoc   the isa string grammar, canonical order, default versions
#     src/unpriv/*.adoc        each extension's stated dependencies and incompatibilities
#     src/profiles/rva20.adoc, rva22.adoc, rva23.adoc, rvb23.adoc  the profiles' mandatory sets
#   llvm-project 7ddb67460b168b17ebb263dc99bf956b56d7e517
#     llvm/lib/Target/RISCV/RISCVFeatures.td  cross-check of versions and implications
#
# each row's revision is the ratified version in the isa string's spelling, and
# a version a string spells must equal it. a row with no revision has no
# version stated by any ratified specification, so a string may not spell one
# for it: ss1p11, ss1p12, ss1p13, sv39, sv48, sv57, svbare and ssctr. the
# profile names state a privileged architecture version in the name and none
# for the extension, and the manual's supervisor chapters state none for the
# translation modes and svbare (llvm lists svbare at 1.0, a tool's choice, not
# a specification's). the manual states smctr at 1.0 and describes ssctr as
# essentially identical, without a version of its own. extensions the manual
# does not list as ratified (the p extension, sdtrig, sdext, smaia, ssaia, zvt
# and the rest) are absent
#
# the conditional dependencies of the c and zce extensions (c brings zcf at
# rv32 with f, and zcd with d) are the catalog's combinations
#
# lines, one record each, fields separated by blanks:
#   row <name> <revision> <implied>...
#     an extension, its id the count of rows before it, its revision `-` for none, then the atoms selecting it brings
#   axis <name> <value>...
#     an execution state axis and its values, in the order of the set's axes, which number on from the rows
#   level <name> <kind> <atom>...
#     a level of kind arch, profile, cpu or psabi, the extensions it selects and the state values, as `axis=value`, it sets
#   alias <key> <name>...
#     another key a consumer spells, naming the rows and levels after it
#   conflict <a> <b>
#     two atoms no selection may hold together, the lower first
#   combination <by> <when> <implied>
#     `by` brings the comma list `implied` while every atom of the comma list `when` is held
#
# an atom is a row's or a level's name, or a state value as `axis=value`. each row's handle is its name by gen's one rule
# (emit.ident), as `zext.h` is ZEXT_H and `3dnow` _3DNOW, and a state value's is the same of `axis=value`, as XLEN_32
