# the risc-v register file: the quantities it scales by, its classes, the
# integer, floating-point and vector registers, the control and status state
# floating-point and vector instructions read and write, their abi names and
# their dwarf numbers
#
#   quantity <name> | unit=<bits> least=<m> most=<m>          a power of two multiple of unit, from least to most
#   bound <quantity> | when=<requirement> least=<m> most=<m>  the multipliers it takes while the requirement holds
#   binding <slot> | quantity=<name>                          the quantity a width's slot binds under every state
#   class <name> | kind=<kind> width=<scaled> count=<scaled>  a class, kind general, float, vector or system
#   register <name> | class= number= bank= ...                a row, or a run `a0..a7` numbered and banked on from the first
#   alias <name> | <register>                                 a further spelling, or a run of them over a run of registers
#   column <name> | format=<format>                           a debug column, dwarf or codeview
#   number <column> <register> | <number>                     a register's number in the column, or a run's from the first
#
# a scaled amount is fixed:per:scale, fixed bits plus per bits times the
# multiplier of slot scale. a register's offset and stride are 0:0:0 and its
# count 1:0:0 unless it says otherwise, it is at one place, a write through it
# keeps the rest of its bank, and its flags are zero, link, stack, accrued or
# length. a requirement is atoms split by spaces, an extension or a state value
# as `xlen=32`, with `!` before an atom the requirement must not hold, and its
# alternatives split by `|`. no source of the generator states any of these,
# so no line overrides one
#
# an x, f and v register is its whole bank, so a write through it has no rest
# and keeps, the one fact check admits there: under rv64 the w instructions
# sign-extend their 32-bit results through the 64-bit register
# (src/unpriv/rv64.adoc, "Register State"), and a write of a narrower format
# into an f register nan-boxes it (src/unpriv/d-st-ext.adoc, "NaN Boxing of
# Narrower Values"), so either write covers its whole register. a field csr is
# written through its own address alone and keeps the rest of the csr that
# holds it, so frm and fflags share fcsr's bank and vxrm and vxsat vcsr's

quantity xlen | unit=32 least=1 most=4 | an x register's width, src/unpriv/rv32.adoc and src/unpriv/rv64.adoc, its domain reaching rv128's 128 bits, which no axis value states | -

quantity sew_min | unit=8 least=1 most=1 | the narrowest element width vtype may set, src/unpriv/vector-common.adoc "Vector Type Register, vtype" | -
