# the extensions that restate a file's instructions on the x registers in
# place of the f registers, and what the restated rows need
#
#   restate <file> <suffix> | requires=<requirement>   each standard record of the file but the transfers is a row of its
#                                                      own under the requirement, its key the record's and the suffix
#   transfer <mnemonic> | unrestated                   a load, store or move between the files no restatement holds
#   format <letter> | <bits>                           a floating-point format's letter in a mnemonic and its bits
#   pair <arg> | position=<field>                      the position a restated register argument wider than the row's
#                                                      x registers takes, an aligned pair of them
#
# zfinx adds the instructions of f, zdinx those of d and zhinx those of zfh,
# each but its transfers, accessing the x register of the number an f register
# would have had. zhinxmin holds fcvt.s.h and fcvt.h.s, and fcvt.d.h and
# fcvt.h.d when zdinx is present too. the compressed files are not restated,
# their every instruction being a transfer. at rv32 a double operand is an
# aligned pair of x registers, so the zdinx rows of the files of every width
# are stated at each width. every restated row conflicts with its f row, since
# zfinx conflicts with f and the restating extensions imply zfinx as d and zfh
# imply f. an operand's format is its mnemonic's last letter, but for a
# conversion between formats, `fcvt.<rd>.<rs1>`, which names its destination's
# first. riscv-opcodes states none of this, so no line overrides it
