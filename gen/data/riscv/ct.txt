# the constant-time classes of the riscv rows, which riscv-opcodes does not state
#
#   independent <mnemonic> | when=<requirement> keeps=<inputs>
#       every row of the mnemonic depends on no input under the requirement but
#       those it keeps, each an argument of the row naming its operand or a
#       register of the file no operand names, none when it keeps none
#
# a requirement is spelled as the files topic spells one. every row of a
# mnemonic no line names is dependent on every input. a listed mnemonic that
# names no row is refused, and so is a mnemonic listed twice. a row's class
# covers its timing alone: the address of an access and the condition and
# target of a transfer always matter, and the walk reads them from the effect.
#
# the lists, from the riscv-isa-manual at 36fdac54a526:
#
# - zkt 1.0 (src/unpriv/zkt.adoc "Zkt listings", the version in
#   src/unpriv/preface.adoc): every instruction it lists, which have
#   data-independent latency under zkt. its hint forms are rows of their own
#   (hints.txt), so they stay dependent as "Specific Instruction Rationale"
#   excludes them. rv32 and rv64 columns need no line, since each row already
#   requires its width. the carried multiply rows of mach's riscv model (mul,
#   mulh, mulhsu, mulhu and mulw under m and zkt) are the rvm table's lines
# - the scalar integer loads and stores under zkt (src/unpriv/zkt.adoc,
#   "Background", lines 104 to 113): the audit rules make a secret in the
#   address of a load or store a violation and nothing else of it, so the
#   data a load or store moves is no input under zkt. floating-point loads and
#   stores stay dependent, as zkt excludes floating point
# - zvkt 1.0 (src/unpriv/zvk.adoc "Zvkt", the version in
#   src/unpriv/preface.adoc): every instruction it lists, under zvkt, each
#   keeping what Zvkt_diel_def leaves out of data-independent latency: the
#   mask v0, vl, vtype and, as a value that is no data operand, vstart. the
#   carry and borrow forms read v0 as data, so they keep no v0, and
#   vrgather.vv, vrgatherei16.vv, vrgather.vx, vslideup.vx and vslidedown.vx
#   keep vs1 or rs1, which the list exempts as control. the list names vsub.vv
#   and vsub.vx twice, and each is one line here. the shift section's note
#   exempting shift amounts is a comment of the source, not its text, so the
#   shifts keep nothing more. the vector crypto instructions the manual makes
#   always data-independent take no line, so they stay dependent
#
# riscv-opcodes states no timing, so no line overrides it
