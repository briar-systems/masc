# x86-64 and 32-bit x86

One set serves both architectures, `x86_64` and `x86`. Its one syntax is
`intel`: Intel's operand order, no register prefix and no size suffix on the
mnemonic.

| fact               | x86                                                   |
|--------------------|-------------------------------------------------------|
| line comment       | `#`                                                   |
| separator          | `;`                                                   |
| `.align n`         | n bytes                                               |
| integer data       | `.byte` 1, `.short` 2, `.value` 2, `.word` 2, `.long` 4, `.quad` 8 |
| symbol kind prefix | `@` or `%`, as `@function`                            |

## Directives of the set

| directive                     | meaning                                            |
|-------------------------------|----------------------------------------------------|
| `.intel_syntax noprefix`      | read what follows in Intel syntax, the set's one syntax |
| `.att_syntax`                 | refused                                            |
| `.code16`, `.code32`, `.code64` | switch the code width for the statements after it |
| `.isa selection`              | restate the whole selection, as `.isa x86-64-v3,avx2` |

```
$ masc assemble att.s -t linux-x86_64 -o att.o
error[asm.refused] `.att_syntax` is not allowed. x86 is read in Intel syntax, as `.intel_syntax noprefix` states
  @ att.s:1:1
1 | .att_syntax
  | ^^^^^^^^^^^
```

The code width is state, not an extension: x86_64 objects are entered at 64
bits and x86 objects at 32. `.code32` inside an x86_64 object reads the
statements after it as 32-bit code:

```
    .align 16
    .code32
    inc eax
    .code64
    jmp .Lhidden
```

assembles `inc eax` to the one byte `40`. The object records no width, so
disassembly reads every byte at the architecture's width (see
[disassembly](disassembly.md)).

## Operands

Registers are written by name, x87's as `st(1)`, without regard to case.
Immediates are the expressions of [the source page](source.md#expressions).
A register's name is never read as a symbol.

Memory is written

```
<size> ptr <segment>:[<base> + <scale>*<index> + <displacement>]{1to<n>}
```

with each part left out when the address has none. The size words are
`byte`, `word`, `dword`, `fword`, `qword`, `tbyte`, `xmmword`, `ymmword` and
`zmmword`. Memory written with no size reads as the code width for `call`,
`jmp`, `push` and `pop`, and otherwise as the one size the instruction takes.
Where more than one size reads it, it is refused:

```
$ masc assemble m1.s -t linux-x86_64 -o m1.o
error[asm.refused] the operand states no size, and more than one size reads it
  @ m1.s:1:5
1 |     add [rax], 1
  |     ^^^
```

`add eax, [rax]` reads, and disassembles as `add eax, dword ptr [rax]`. A size
word on an address that is never accessed, as `lea rax, qword ptr [rcx]`, is
read and ignored. A size that differs from a stated width is refused.

`rip` is the base of a rip-relative address. Its displacement may name a
symbol and an addend, as `[rip + table + 8]`, and becomes a pc-relative
relocation from the instruction's end.

AVX-512's opmask and zeroing go in braces after the operand they decorate,
as `vaddps zmm0 {k1}{z}, zmm1, zmm2`.

Prefixes are written as words before the mnemonic: `lock`, `rep`, `repe`,
`repz`, `repne`, `repnz`, `{nf}`, `addr16` and `addr32`.

```
    lock add dword ptr [rax], 1
    rep movsb
1:  mov al, byte ptr fs:[rax + 4*rcx - 8]
    fld st(1)
    vaddps zmm0 {k1}{z}, zmm1, zmm2
    movabs rax, 0x1122334455667788
```

assembles under `--isa x86-64-v4`. Disassembly prints the string operands
`rep movsb` fixes, as `rep movsb byte ptr es:[rdi], byte ptr [rsi]`.

## Encoding forms

Where one instruction has several encodings, the shortest is the default. A
marker in braces before the mnemonic chooses another:

| marker              | form                                                    |
|---------------------|---------------------------------------------------------|
| `{disp8}`, `{disp32}` | the displacement's width, or a branch's wider target  |
| `{rex}`, `{rex2}`   | a prefix no register needs                              |
| `{load}`, `{store}` | the direction of a register-to-register form that has both |
| `{vex}`, `{vex3}`, `{evex}` | the encoding space and the long vex form        |
| `{addr}`            | an address-size override on an address no register sizes |

```
    {vex3} vaddps xmm0, xmm1, xmm2
    {disp32} mov eax, dword ptr [rax]
```

disassembles to the same text, markers included.

## Relocation specifiers

A specifier follows a bare symbol name and reads without regard to case.

| format | operand                          | specifiers                                         |
|--------|----------------------------------|----------------------------------------------------|
| ELF    | call or jump target              | `@PLT`                                             |
| ELF    | displacement or 32-bit immediate | `@PLT`, `@GOTPCREL`, `@GOT`, `@GOTOFF`, `@TPOFF`, `@DTPOFF`, `@GOTTPOFF`, `@TLSGD`, `@TLSLD`, `@TLSDESC`, `@TLSCALL`, and on i386 `@NTPOFF`, `@INDNTPOFF`, `@GOTNTPOFF`, `@TLSLDM` |
| ELF    | 64-bit immediate                 | `@GOT`, `@GOTOFF`, `@PLTOFF`, `@TPOFF`, `@DTPOFF`  |
| Mach-O | displacement or 32-bit immediate | `@GOTPCREL`, `@TLVP`                               |
| COFF   | displacement or 32-bit immediate | `@SECREL32`, `@IMGREL`                             |

Each is bound only on the architectures that relocate it. On x86-64 ELF a
call to a symbol is `R_X86_64_PLT32` with or without `@PLT`, and a
`@GOTPCREL` load is `R_X86_64_REX_GOTPCRELX`.

## x86-64 example

```
# a comment
    .text
    .globl add
    .type add, @function
add:
    mov rax, rdi
    add rax, rsi
    ret
    .size add, . - add
```

```
$ masc assemble a.s -t linux-x86_64 -o a.o -v
a.s: 1 section, 1 symbol, 0 relocations, written to a.o as elf
$ masc disassemble a.o -t linux-x86_64
	.globl add
	.type add, @function
	.size add, 7
	.section .text, "ax", @progbits
add:
	mov rax, rdi
	add rax, rsi
	ret
```

## 32-bit x86

`linux-x86` names no instruction set of its own, so it needs `--isa`:

```
# 32-bit x86
    .globl inc32
inc32:
    mov eax, dword ptr [esp + 4]
    add eax, 1
    call other@PLT
    ret
```

```
$ masc assemble i386.s -t linux-x86 --isa i386 -o i386.o -vv
note[target] linux-x86, abi sysv32, isa i386, format elf
i386.s: 1 section, 2 symbols, 1 relocation, written to i386.o as elf
$ masc disassemble i386.o -t linux-x86 --isa i386
	.globl inc32
	.globl other
	.section .text, "ax", @progbits
inc32:
	mov eax, dword ptr [esp + 4]
	add eax, 1
	call other@PLT
.Ltmp0:
	ret
```

The call is `R_386_PLT32` against `other`.

## COFF and Mach-O

On `windows-x86_64` a symbol's kind is stated with `.def`, `.scl`, `.type`
and `.endef`, and `.section` takes COFF's flag letters:

```
    .text
    .globl add
    .def add
    .scl 2
    .type 32
    .endef
add:
    lea rax, [rcx + rdx]
    ret
    .section .rdata, "dr"
value:
    .long 42
```

```
$ masc assemble coff.s -t windows-x86_64 -o coff.obj -v
coff.s: 2 sections, 2 symbols, 0 relocations, written to coff.obj as coff
```

On `darwin-x86_64` sections are `segment,section` and the shorthand
directives enter them:

```
    .text
    .globl _add
_add:
    lea rax, [rdi + rsi]
    ret
    .cstring
L_msg:
    .asciz "hello"
    .subsections_via_symbols
```

```
$ masc assemble macho.s -t darwin-x86_64 -o macho.o -v
macho.s: 2 sections, 1 symbol, 0 relocations, written to macho.o as macho
```
